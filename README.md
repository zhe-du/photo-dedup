# photo-dedup —— 照片合并去重工具

零依赖的 Node.js 命令行工具：把多个文件夹里的照片**按内容**去重后合并到一个文件夹，可选按拍摄时间重命名排序。

手机相册、旧电脑、网盘备份、U 盘里各存一份，同一张照片落了三四个副本，文件名还全不一样（`IMG_0001.jpg` / `微信图片_20240102.jpg` / `副本(2).jpg`）——这个工具就是干这个的。

```bash
node photo-dedup.js "D:/备份/手机相册" "E:/旧电脑/照片" --out "D:/照片合并" --dry-run
```

先跑 `--dry-run` 看报告，确认没问题再去掉它。

## 为什么不用现成工具

| 方案 | 问题 |
|---|---|
| Windows 资源管理器 / macOS 访达 | 只能在同一目录内比对，跨盘跨目录不行 |
| Duplicate Cleaner、Gemini 2 之类 | 要安装、常用功能在付费墙后面 |
| 网盘"重复文件清理" | 得先全传上去，耗时且涉及隐私 |

这个工具是**一个 js 文件**，Node.js >= 18 直接跑，不装包、不联网。

## 原理

1. 递归收集所有源文件夹里的文件（跳过输出目录自身，避免自己吃自己）
2. **按文件大小分组**——大小唯一的文件不可能有重复，直接跳过哈希，这在几十万文件的目录下能省掉绝大部分 I/O
3. 只对同大小的文件计算**内容哈希**（默认 SHA-256，可换 MD5 / SHA-1 / SHA-512）。哈希相同即内容相同，**完全不看文件名和修改时间**
4. 每组用 `--keep` 策略选出一个"胜者"，其余判定为重复
5. 胜者**移入**输出目录，成功后该组的重复文件才删除或移入回收目录
6. 合并时若不同内容撞同名，自动加 `(1)`、`(2)` 后缀，**绝不覆盖**

哈希在 `worker_threads` 里并发执行，文件多时自动开多线程（`--jobs`）。

## 快速开始

```bash
git clone https://github.com/zhe-du/photo-dedup.git
cd photo-dedup

# 看帮助
node photo-dedup.js --help

# 演练：只出报告，不动任何文件
node photo-dedup.js "照片/备份A" "照片/备份B" --out "照片/合并后" --dry-run

# 正式合并去重
node photo-dedup.js "照片/备份A" "照片/备份B" --out "照片/合并后"
```

不需要 clone 也行：只把 `photo-dedup.js` 拷出去就能用。Windows 下也可以直接调 `photo-dedup.cmd`（等价于 `node photo-dedup.js`）。

## 常用示例

```bash
# 保留最新一份，重复文件移入回收目录而不是直接删除
node photo-dedup.js "照片/备份A" "照片/备份B" --out "照片/合并后" --keep newest --trash "照片/回收"

# 合并后按拍摄时间重命名：2024-01-02_030405_原名.jpg
node photo-dedup.js "照片/备份A" "照片/备份B" --out "照片/合并后" --sort-by-date

# 只合并不删重复（先看看效果）
node photo-dedup.js "照片/备份A" --out "照片/合并后" --no-delete

# 分批往同一个输出目录里加，跳过已合并过的内容
node photo-dedup.js "照片/备份C" --out "照片/合并后" --skip-existing

# 只要图片，8 线程
node photo-dedup.js "照片/备份A" --out "照片/合并后" --include-ext jpg,png,heic,webp --jobs 8
```

## 参数

| 参数 | 说明 |
|---|---|
| `--out <目录>` | 合并输出目录（默认：第一个源文件夹同级的 `合并后`） |
| `--dry-run` | 只分析、输出报告，**不做任何移动/删除** |
| `--hash <算法>` | `md5` / `sha1` / `sha256` / `sha512`（默认 `sha256`） |
| `--no-delete` | 只合并，不删除重复文件 |
| `--trash <目录>` | 把重复文件移动到该目录而不是删除（同名自动加后缀） |
| `--keep <策略>` | 重复组保留策略：`largest`（默认）/ `smallest` / `newest` / `oldest` / `first`——注意下面的说明 |
| `--jobs <n>` | 并发哈希线程数，`0`=自动（默认），`1`=单线程 |
| `--hash-all` | 即使文件大小唯一也计算哈希（默认跳过，报告里这些文件 `hash` 为 `null`） |
| `--skip-existing` | 输出目录已有相同内容的文件时，不再重复合并 |
| `--sort-by-date` | 按拍摄时间重命名：优先 EXIF，其次文件名内嵌日期，最后文件修改时间 |
| `--exif-only` | 排序时只认 EXIF，不回退 |
| `--log <文件>` | 报告 JSON 路径（默认在当前目录生成带时间戳的报告） |
| `--min-size <字节>` | 忽略小于该体积的文件 |
| `--include-ext <列表>` | 只处理指定扩展名，逗号分隔 |
| `--quiet` | 只输出汇总 |
| `--help` | 帮助 |

### 关于 `--keep` 的真实行为

这里有个容易误会的地方，说清楚：

**同一个重复组里的文件内容完全相同，那它们的大小必然也相同。** 所以 `largest` / `smallest` 在正常场景下没有任何区分度，实际效果等同于 `first`（按源文件夹顺序取靠前的）。默认值保留 `largest` 只是为了兼容旧版本。

真正有意义的策略是：

| 策略 | 实际含义 |
|---|---|
| `newest` | 保留修改时间最新的那份（推荐，通常来自最近一次同步） |
| `oldest` | 保留最旧的 |
| `first` | 保留源文件夹参数里排在最前面的那个（推荐，结果可预测） |

## 报告

每次运行都会生成一份 JSON 报告（默认 `dedup-report-时间戳.json`，`version: 2`）：

| 字段 | 内容 |
|---|---|
| `winners` | 保留的每个文件（路径、大小、哈希、mtime） |
| `duplicates` | 判定为重复的文件 |
| `moved` / `deleted` / `trashed` | 实际移动 / 删除 / 移入回收的清单 |
| `skippedExisting` | 因输出目录已有相同内容而跳过（配合 `--skip-existing`） |
| `moveFailures` / `hashErrors` | 移动失败、哈希失败的文件 |
| `hashSkippedUnique` | 因大小唯一而跳过哈希的文件数 |
| `freedBytes` / `elapsedMs` | 释放空间、耗时 |

报告可以直接用 `jq` 或者丢给脚本做二次处理。

## 安全设计

去重工具天生是**破坏性**的，所以这块写细一点，逐条对应代码：

1. **先移动，后删除。** 只有当胜者真的成功移入输出目录了，该组的重复文件才会被删/回收。胜者移动失败（权限、占用、磁盘满），整组重复文件原样保留。
2. **`--dry-run` 完全只读**：不建输出目录、不移动、不删除。
3. **`--trash` 代替删除**：重复文件移到你指定的回收目录，确认无误后再手动清空。
4. **不覆盖任何文件**：目标目录已有同名但内容不同的文件时，加 `(1)` 后缀。
5. **删之前会重新确认文件还在**（`existsSync`），已经不存在的不计数、不报错。
6. 跨盘移动自动回退为「复制 + 删除源文件」。

## 限制

- **只做字节级去重。** 判断"相同"是内容逐字节一致。下面这些**不会**被判为重复：
  - 同一张照片的原始 JPEG 和微信/QQ 转发后重新压缩的版本
  - 截图另存、HEIC 转成 JPG 之后的副本
  - 加了水印或改过尺寸的版本

  需要"看起来像"就去重，那是感知哈希（pHash/dHash）的活，不是这个工具的定位。
- **符号链接会被跳过**：用 `Dirent.isFile()` 判断，软链接不算普通文件，不会跟进。
- **HEIC 的 EXIF 采用启发式扫描**（在文件头 32MB 内找 `Exif\0\0` 标记）。绝大多数机型可用，个别极端布局取不到拍摄时间，会回退到文件名/修改时间（除非加了 `--exif-only`）。
- **单进程内存**：文件元数据全在内存里，几百万文件级别需要较大内存；哈希本身是流式的，不会把照片读进内存。

## 声明

### 用途

只做一件事：把多个目录里的文件按内容去重合并到一处，可选按拍摄时间改名排序。
它不是图片管理软件：不做缩略图、不做相册浏览、不识别画面内容、不修复损坏文件。

### 数据与隐私

- 纯本地运行，**不联网、不上传、不写云端日志**、无遥测
- 读取的是你指定的目录；**写入**只有两处：`--out` 输出目录、`--trash` 回收目录
- 报告 JSON 里会记录**完整的绝对路径**（含用户名）。把报告发到公开 issue 前请自己过一遍
- 不做任何图像解码，只读文件字节算哈希；不修改照片本身的内容

### 安全

- 不需要管理员权限；不安装服务、不写注册表、不开端口
- 只使用 Node.js 标准库（`fs` / `path` / `crypto` / `os` / `worker_threads`），**零第三方依赖**，没有 `postinstall`，代码里没有任何网络请求
- ⚠️ **这是唯一需要你警惕的地方：默认会删除文件。** 第一次用请务必先 `--dry-run`，正式跑时建议配合 `--trash`，确认回收目录里的东西确实都是废的，再清空
- 已知的删除保护见上面「安全设计」六条

### 兼容性与限制

- Node.js >= 18，Windows / macOS / Linux 均可
- 已在 Windows 11 + Node 22 上验证；PATH 里要有 `node`
- 不处理：云盘占位符文件（OneDrive「按需文件」未下载时读取会触发下载或失败）、正在被其他程序写入的文件、加密压缩包内的文件
- 文件名含 emoji / 特殊字符依赖文件系统行为，不做额外转义
